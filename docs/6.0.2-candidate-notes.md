# Gantry 6.0.2-rc.1 candidate

This is the provisional **shared change engine** candidate after published
6.0.1. It does not replace the immutable 6.0.1 release or establish a new public
release. Candidate packaging and staging acceptance are recorded on task 342
and the draft PR. PHP **8.5.x only**; native Joomla verification targets the
staging clone. Gantry 5 and the PHP 8.4 proving site stay outside this work.

## Changed persistence

- Native admin and REST outline/layout/settings writes enter one core engine
  for revision checks, theme locking, save recovery and undo.
- A theme-wide content/generation revision invalidates stale open editors,
  including after parent/sibling changes or an undo that restores equal bytes.
- Preview validates the proposed data without saving, compiling CSS or firing
  save events. It is separate from rendered saved-page preview.
- Native Format2 allocates deterministic document-local implicit identities and
  reserves explicit grid/block/particle IDs before traversal. Unchanged layout
  GETs and no-write previews expose the same node IDs across requests.
- Durable private history survives normal cache clearing, retains at most 20
  changes and preserves the current undo target through timestamp/mtime skew.
- Native Joomla database transactions and exact authoritative-file snapshots
  support recovery. Interrupted writes block further edits for verified
  operator recovery. See [the limits and recovery procedure](shared-changes.md).
- Layout/index reads rebuild missing/stale indexes in memory without saving.
  Legacy Joomla template-style aliases require explicit migration; catalogue
  reads no longer silently copy outline configuration or rewrite style rows.
- Native assigned-outline deletion now matches REST protection and is refused
  before invoking Joomla's menu-reassigning delete model, including in preview.
  Menu assignment changes remain outside this recovery surface.
- Native duplication passes the requested title to Joomla's rename writer
  without adding a second theme prefix. Native UI/API title and copied-data
  agreement are verified on the staging clone.
- Native **Theme changes** provides summaries and confirmed latest-change undo.
  Existing client policy/text, snapshot restore and design-pack apply mutations
  also enter the same engine while retaining their own permissions. Legacy
  whole-theme ZIP import is refused; it exceeds this recovery boundary.
- General native save/preview actions require the same settings-administrator
  permission as REST; module-manager JSON admission cannot authorize theme writes.
  Explicitly approved restricted-client text keeps its existing narrow policy.

## Added Joomla endpoints

Each route follows `/api/index.php` and uses existing Joomla core token auth
and the same Gantry/template administrator ACL as the original nine operations:

- `GET /v1/gantry/themes/{theme}/changes`: current revision and safe history.
- `POST /v1/gantry/themes/{theme}/changes/preview`: no-write plan for create,
  rename, delete, layout or settings, using the same validation as its save.
- `POST /v1/gantry/themes/{theme}/changes/undo`: restore the latest change under
  a matching current revision; return a new revision/change identity.

Existing outline/layout/settings endpoints retain their bounded data surface.
Outline creation additionally accepts an optional client revision, allowing a
create preview to become a checked commit while preserving the old body shape.
Successful writes expose the resulting revision/change ID in response headers,
including the empty DELETE response. Admin Swagger/OpenAPI includes the three
new operations. No auth provider, custom token, separate bridge or standalone
component is added. Basic authentication remains disabled.

## Verification state and remaining gates

Established source evidence: **76 native change-engine fixture checks on actual
PHP 8.5.3**, including real process contention and forced interruption;
**57 native API/cache checks** and **54 administrator permission fixture
checks**, plus **52 deterministic native layout identity checks** on the same
runtime. CI includes these alongside existing runtime,
API input and dependency checks.
The separate actual Joomla Database SQLite fixture passes **22 checks** for
native reference/NULL/transaction semantics. It reports one upstream SQLite
PHP 8.5 bootstrap deprecation and does not replace the staging MariaDB gate.
This document does **not** claim the staging round-trip has passed. Actual
Joomla token/DB/CSS/admin/front-end preservation and log results belong to the
candidate's task/PR evidence after execution.

Menus, assignments and Grav position management are outside this slice. Joomla
is the current native database adapter; WordPress mutation paths fail closed
until that adapter and its runtime gate are implemented (read-only admin remains
available). There
is no performance claim, compiled render bundle, new asset pipeline, extension
API registry, MCP endpoint, metadata audit or Template Club installer in this
candidate. The [accepted roadmap and gates](gantry6-roadmap.md) remain binding.
Mutation acceptance targets Joomla; WordPress writes remain disabled pending
its native database adapter, and no WordPress/Grav runtime pass is claimed.
